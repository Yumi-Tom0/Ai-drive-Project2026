# TODOアプリ V2 要件定義書

ファイルパス: `docs/todo/v2/01_requirements_v2.md`

## 1. 概要

本ドキュメントは TODO アプリ V2（発展課題）の要件を定義するものです。
V1 の機能・API・DB・レスポンス形式を維持したまま、優先度（`priority`）の管理および条件指定による絞り込み機能を追加します。

## 2. V1との互換性・維持条件

* **V1機能の完全保持**: `/api/v1/todos` および `/todo` 画面は一切変更せず、独立して動作し続けること。
* **データ分離**: V1のデータ (`todo_tasks`) は変更せず、V2専用のテーブル (`v2_todo_tasks`) を新設して管理すること。データ移行は行わない。
* **基本エラーハンドリングの共通化**: V1で定義した統一レスポンスフォーマット（`status`, `code`, `message`, `details`）を継承すること。

## 3. V2 追加要件

### REQ-V2-01: 優先度の追加
* TODO項目に `priority`（優先度）属性を追加する。
* 選択肢: `'low'`, `'normal'`, `'high'` の3種類。
* 省略時のデフォルト値: `'normal'`。

### REQ-V2-02: 絞り込み一覧取得 (`GET /api/v2/todos`)
* クエリパラメータによるフィルタリング機能を提供する。
  * `completed`: `true` または `false`（文字列）。省略時は全件対象。
  * `priority`: `'low'`, `'normal'`, `'high'` のいずれか。省略時は全件対象。
* 条件なし（クエリ指定なし）の場合は、V2の全件を取得する。
* パラメーター化クエリを使用して安全に検索を実行すること。

### REQ-V2-03: 優先度付き新規登録 (`POST /api/v2/todos`)
* タイトル（`title`）と任意の優先度（`priority`）を受け取り登録する。
* `priority` を省略した場合は `'normal'` として登録する。

### REQ-V2-04: 部分更新 (`PATCH /api/v2/todos/:id`)
* `isCompleted`（完了フラグ）または `priority`（優先度）の**少なくとも一方**を受け取り更新する。
* 双方同時に指定された場合も正しく更新されること。

### REQ-V2-05: 削除 (`DELETE /api/v2/todos/:id`)
* 指定されたIDのTODOを削除する（V1と同等の挙動・`204 No Content` を返却）。

### REQ-V2-06: V2専用画面 (`/todo-v2`)
* `/todo-v2` のURLでV2専用の画面を提供する。
* 登録時に優先度（low / normal / high）を選択可能。
* 完了状態（すべて / 未完了 / 完了）および優先度（すべて / low / normal / high）によるリアルタイム絞り込み表示が可能。
